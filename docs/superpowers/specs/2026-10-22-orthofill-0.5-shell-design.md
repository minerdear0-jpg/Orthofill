# Orthofill 0.5: запись как оболочка (Cisco IOS для врача)

Дата: 22.10.2026. Идея и решения заказчика из разговора 22.10 (после 0.4 beta 1).
Макеты: `.superpowers/brainstorm/3310756-1792665868/content/shell-tab.html`,
`shell-canvas.html` (рабочие, не в git).

## Зачем

Сейчас врач пишет запись через запятые, а программа её **разбирает и
угадывает**: «лигатурная, перепел, дуга верх 16х25». Отсюда весь класс ошибок
0.2–0.3: не то понято, лишняя строка, «проверьте». Запятая — лишняя работа
врача, разбор — лишняя работа программы, и ошибки рождаются между ними.

Заказчик: врач — программист на своём языке, человек — валидатор. Поле
записи становится **оболочкой** с правилами ввода, как Cisco IOS:
сокращения разворачиваются до полного, полное — это **тексты пунктов,
которые врач сам загрузил в xlsx**. «Системы нет, а функция есть»: отдельного
языка команд нет — язык ввода и есть пресет врача.

Первая проверка человеком происходит **при вводе**: врач видит, в какой пункт
попала строка, до протокола. Программе больше нечего угадывать.

## Решения заказчика (22.10)

1. **Одна строка — один путь по дереву пресета**, без запятых. Ввод
   «естественный» — сокращениями, но оболочка сама выдаёт путь **часть за
   частью** из структуры.
2. **Как Cisco IOS**: сокращение разворачивается Tab до полного; полное —
   текст узла пресета; варианты уровня показываются; неоднозначное не
   угадывается.
3. **Строка после выбора — путь по дереву** (не «слова врача»): врача с
   начала приучаем к структурированному вводу, который он сам определяет в
   своём xlsx.
4. **Короткие имена узлов не нужны**: тексты пунктов длинные — главное, что
   врач **сразу при вводе видит ровно тот текст**, что попадёт в протокол.
5. **Свободного текста в оболочке нет.** Свою жалобу или особую деталь врач
   пишет **сам в финальном протоколе**. Разбор свободного текста программой
   («варианты ошибок») — закрыт.
6. **Карточка как Canvas** (web-интерфейсы Claude, ChatGPT, Qwen): поле
   ввода — оболочка, рядом — живой документ протокола, его правят прямо на
   месте.
7. **Предсказание дешёвое**: файл врача записан сверху вниз, слева направо —
   **порядок файла задаёт направление** подсказки; **родитель выбранного
   значения известен** — его ветки и следующая группа — первые кандидаты.
8. Поле ввода — по-прежнему RAW (то же поле записи, с правилами оболочки).

## Цели

1. Запись приёма набирается строками-путями; каждая строка однозначно
   указывает пункт (код) пресета.
2. Подсказка следующего куска пути и следующей строки — по порядку файла,
   родителю и частотам врача; Tab принимает кусок, `?` — ветки уровня.
3. Протокол собирается из путей **без разбора и угадывания**; свой текст
   врача в протоколе сохраняется при пересборке.
4. Переход: старые записи и история врача переводятся в пути; разбор через
   запятую остаётся только для перехода.

## Не цели

- Распознавание речи, ИИ-модели, обучение на данных (предсказание —
  порядок дерева + родитель + частоты).
- Свободный текст в оболочке и любая «догадка» о смысле.
- Новый формат пресета: дерево, коды, логика (И/ИЛИ/НЕ) — как в 0.2–0.3;
  добавляется только ветка «нет» (отмена пункта).

## Анти-цели

- Строка, которая попала не в тот пункт, а врач этого не видит.
- Оболочка угадывает при неоднозначном сокращении.
- Ввод ждёт: подсказка — мгновенно (дерево пресета — сотни узлов).
- Свой текст врача в протоколе теряется при пересборке.
- Врач обязан набирать верхние разделы («Лечение ›»), чтобы дойти до пункта.

## Оболочка

### Строка

- Строка — путь от раздела к пункту, полностью развёрнутый:
  `Лечение › Смена дуги на верхней челюсти › на верхней челюсти 0.016×0.025" NiTi`.
  Разделители `›` ставит оболочка. Готовая строка подсвечена «понято», справа
  (или в холсте) — код и текст пункта.
- Набор — по началу **любого слова** текста узла, без учёта регистра и «ё»;
  числа и размеры — как написаны врачом и в пункте («16х», «0.016×0.025»,
  «16x25» — одно и то же: х/x/×, точка/без).
- Пока набранное однозначно на текущем уровне — серым показан остаток узла;
  **Tab** разворачивает. Неоднозначно — список вариантов (как IOS `?`),
  частые у врача — сверху. **`?` или двойной Tab** — все ветки уровня.
- Слово, которое не подходит ни к одной ветке уровня, подсвечивается сразу.
- **Enter** на листе — строка готова, новая строка. Enter на группе — список
  её веток (строка ещё не готова). Ctrl+Enter — подтвердить протокол (как
  сейчас).
- Backspace по развёрнутому куску — вернуть набранное сокращение (как отмена
  дополнения); строка правится как текст, путь перепроверяется.

### Tab — карусель, Enter — подтверждение (заказчик, 22.10, перед 0.5 b3)

- **Tab — выбор вариантов (пролистывание), Enter — подтверждение.** Заполнение
  сводится к Tab по деревьям (как пути в Linux) и Enter: «заполнение сводится
  вообще к одному Tab … и выбором вариантов с подтверждением Enter».
- **Зажатый Tab бегает по карусели** вариантов текущего родителя (поведение
  fish), по кругу; Shift+Tab — назад.
- Enter на выбранном: лист — строка готова (новая строка с предсказанием);
  группа — путь развёрнут и сразу карусель её веток (частый выбран).
- Пустая строка: Tab — карусель кандидатов (предсказание выбрано первым),
  Enter — подтвердить предсказание (серую подсказку).
- Набор букв сужает карусель (как в fish); однозначно — Tab разворачивает
  сразу (как дополнение в fish).

### Стрелки (как в fish) — заказчик, 22.10

- В открытом списке вариантов **↑/↓** — выбор, **Enter/Tab** — принять.
- В готовой (или набираемой) строке **←/→** ходят по **уровням пути**
  целиком (кусок пути — одна единица, как слово в fish).
- Если врач **намеренно встал курсором** на уровень (пришёл стрелками и
  остановился — не при наборе и не проходя мимо), **варианты этого уровня
  раскрываются вниз** — соседние ветки того же родителя. ↑/↓ — заменить
  выбранное (например, «верхней» → «нижней» или другой размер дуги), Enter —
  принять. Уровни ниже перепроверяются: подходят к новому родителю —
  остаются (тот же текст листа), нет — снимаются, и строка ждёт Tab.
- Esc — свернуть список, курсор остаётся.

### Отмена пункта — ветка «нет» (заказчик, 22.10)

- Пункт, который стоит по умолчанию или всегда (например, фотопротокол),
  отменяется **путём к его ветке «нет»** в xlsx: `Лечение › Фотопротокол ›
  нет`. Ветку «нет» врач объявляет сам в своём файле — «системы нет, функция
  есть»: отмена идёт по тем же правилам Tab, `?`, стрелок, видна в скелете
  (полоса пункта исчезает).
- Пункт без ветки «нет» отменить в оболочке нельзя — только удалить строку в
  протоколе справа (как свой текст). *(решение исполнителя)*
- Ветка «нет» — новый вид узла в пресете (колонка «Настройки» или текст
  «нет» у листа — решение исполнителя, с проверкой линтера: «нет» без пункта
  по умолчанию — предупреждение).

### Уровни и предсказание

- Верхние разделы набирать не обязательно: первое слово строки ищется по всему
  дереву; найденный узел достраивает путь вверх сам. Совпадения в нескольких
  разделах — список с путём. *(решение исполнителя)*
- **Порядок файла задаёт направление**: кандидаты для новой строки — узлы
  **после** последнего выбранного в порядке пресета (сверху вниз), затем —
  остальные. Внутри уровня — порядок файла, поднятый частотой врача.
- **Родитель известен**: после листа группы первыми идут соседние листы той же
  группы (если группа допускает несколько — тип «И») и следующая группа.
  Группа «ИЛИ» после выбранного листа не предлагает соседей.
- Привычки 0.3 b2 → «следующая строка, которую вы обычно пишете после этой»
  (серым целиком; Tab/→ — принять, Ctrl+→ — по куску пути).
- Словарь врача 0.2 b3 → **синонимы узлов** («торк» → 4g3): синоним
  разворачивается в полный путь. *(решение исполнителя)*

### Холст протокола (Canvas)

- Справа — протокол, собранный из строк-путей и пунктов по умолчанию
  (как сейчас, без разбора свободного текста).
- Строка оболочки под курсором и её место в протоколе подсвечиваются вместе.
- **Скелет протокола** (заказчик): блоки, которые ещё не написаны, показаны
  серыми залитыми полосами — как страница, содержимое которой не загрузилось.
  Строка готова — полоса становится текстом. Ближайший незаполненный блок по
  порядку файла обведён: туда, скорее всего, пойдёт следующая строка (то же
  направление, что у предсказания). Какие блоки показывать скелетом — группы,
  которые врач обычно заполняет (по его истории), и обязательные. *(состав —
  решение исполнителя)*
- **Свой текст** врач пишет прямо в протоколе; он помечен и сохраняется при
  пересборке (привязан к месту — разделу/пункту, после которого написан).
  *(как привязывать — решение исполнителя, см. «Оставлено исполнителю»)*
- Ctrl+Enter — подтвердить: в буфер — протокол как в холсте (со своим
  текстом), в журнал — строки-пути и итог.

## Переход

- **Переключатель** (заказчик, 22.10): оболочка включается переключателем;
  ввод через запятую остаётся рядом, пока **телеметрия (0.4) не покажет**,
  какой ввод быстрее и точнее у этого врача. Переключатель — в окне (рядом с
  «Подсказки»), запоминается для пресета; телеметрия пишет режим у каждой
  записи, чтобы сравнить: время на запись, правки протокола, «Отметить
  ошибку», непонятые слова. *(место переключателя — решение исполнителя)*

- Старые записи (через запятую) в истории врача переводятся в пути тем же
  разбором 0.3, **с подтверждением**: частоты и «следующая строка» берутся
  только из подтверждённых. *(решение исполнителя)*
- В режиме оболочки строка, которую оболочка не поняла, **не попадает** в
  протокол молча: подсвечена, протокол показывает «строка не понята».
  Разбор через запятую — в режиме «как раньше» (переключатель).
- SmartPhrase 0.3 b3: в оболочке, вероятно, лишний (путь уже и есть шаблон
  с полями). Судьба — по данным телеметрии (0.4) после 0.5 b1.

## Телеметрия (0.4) для 0.5

События: строка готова (длина пути, сколько Tab, сколько `?`, сколько
символов набрано против развёрнутых), неоднозначность (сколько вариантов),
«не подходит» на слове, принятое/непринятое предсказание следующей строки, своё
в холсте (длина). Это и есть мера «ввод стал естественным».

## Порядок (предложение исполнителя)

- **0.5 beta 1** — оболочка: строка-путь, разворот Tab, `?`, неоднозначность,
  «не подходит», уровни без раздела, протокол из путей; синонимы из словаря.
- **0.5 beta 2** — предсказание: порядок файла, родитель, «следующая строка»;
  перевод истории в пути.
- **0.5 beta 3** — холст: свой текст в протоколе с привязкой, подсветка
  строка ↔ место; судьба SmartPhrase и разбора через запятую.

## Решения исполнителя по проверке описания

- **Сопоставление слов** (как в анимации `shell-animation.html`): набранные
  слова строки — фильтры «И» по ещё не выбранной части пути, на любом
  уровне; пробел не означает уровень (в текстах пунктов есть пробелы). Tab
  разворачивает путь настолько, насколько он однозначен; `?` — ветки
  следующего неразвёрнутого уровня; «не подходит» — первое слово, после
  которого кандидатов не осталось.
- **Строгость совпадения**: начало любого слова пункта (регистр, «ё»),
  числа — по цифрам (16 ≈ 0.016, 16х25 ≈ 0.016×0.025, х/x/×); формы слова
  («дуга» → «дуги») — по общему началу не короче 3 букв. Смысловых
  совпадений («хор» → «удовлетворительная», «3» → «третьего») нет —
  это **синонимы врача** (словарь 0.2 b3: врач учит их сам, как сейчас).
  Неоднозначно — варианты, без догадки.
- **Эталоны** (xlsx C–F): старые проверяются старым разбором, как сейчас;
  новые «Сохранить как эталон» пишут строки-пути (коды) — формат колонки D
  не меняется, проверка различает по наличию `›`.
- **SmartPhrase в 0.5 b1**: в оболочке не раскрывается (путь и есть шаблон);
  данные фраз сохраняются; судьба — после телеметрии.
- **Правка сгенерированной строки в холсте** (0.5 b3): правленная строка
  становится своим текстом врача, привязанным к этому пункту, и при
  пересборке не перезаписывается (помечена).

## Оставлено исполнителю

- Отображение пути в поле (полный текст каждого уровня или сокращённо с
  полным текстом справа, если строка не помещается) — главное правило: врач
  видит точный текст пункта.
- Привязка своего текста в холсте к месту протокола.
- Клавиша для `?` в русской раскладке (физическая клавиша, как Ctrl-сочетания
  0.2 b7).
- Хранение строк-путей в журнале (коды + набранное).
