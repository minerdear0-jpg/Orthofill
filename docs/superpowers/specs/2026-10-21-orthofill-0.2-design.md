# Orthofill 0.2: пресеты, новый вид протокола, обучение словам врача, редактор

Дата: 2026-10-21. Статус: утверждено заказчиком (после разбора ТРИЗ).
Основа: 0.1 beta 3 (ветка `feature/0.1beta`, коммит `1f117cb`), описание 0.1 —
`2026-10-21-orthofill-0.1beta-design.md`.
Макеты: `.superpowers/brainstorm/2866305-1792601460/content/` —
`window-variants.html` (главное окно, вариант A), `presets.html`
(переключатель, редактор, подсказки), `protocol-view.html` (ранний вид протокола).

## Зачем

Первый день диагностики (21.10, 9 протоколов) показал:

- главная беда — программа **дописывала в протокол то, чего врач не писал**
  (додуманные процедуры). Основная причина исправлена в 0.1 beta 3;
- врач пишет своими словами («торк», «самолинируемая», «на верху»), и каждое
  такое слово сейчас требует новой сборки от разработчика;
- текст протокола в окне трудно проверять глазами: одна мысль разбита на две
  строки, есть повторы («Тип системы / Тип системы: …»);
- xlsx, открытый в Excel, блокирует запись эталона; переименованный файл теряется;
- карточки бывают **разных типов** (активация, консультация…), а программа знает
  только один файл и правила, написанные под активацию.

Цель 0.2: несколько типов карточек; врач видит, где проверить протокол; сам учит
программу своим словам и сам правит логику карточки — без разработчика;
xlsx остаётся привычным языком, на котором врач объясняет, чего хочет.

Успех: врач добавляет пропущенный пункт в два действия, а повторно то же слово
понимается само; новый тип карточки (консультация) заводится импортом xlsx и
правкой в редакторе, без новой сборки; диагностика показывает в основном
ошибки логики, а не незнакомые слова.

## Пользователь и окружение

Врач-ортодонт, не программист, работает с Excel. Пресеты правят **и врач, и
ИТ-специалист**. Windows 11, tkinter + sv-ttk, портативная сборка. Карточки
заполняются **после** приёма. Окно часто узкое, «поверх окон» рядом со
служебным ПО. Данные обезличены. У каждого врача — своя копия программы со
своей базой.

## Понятия

- **Пресет** — бизнес-логика одного типа карточки: пункты (разделы, группы,
  варианты, отдельные пункты), правила выбора вариантов, эталоны «запись →
  протокол», словарь слов врача. Хранится в SQLite. Пресет — не файл.
- **xlsx** — формат обмена: импорт пресета из файла и экспорт в файл того же
  формата (A–F + лист «Словарь»).
- **Эталон** — пара «запись → идеальный протокол» внутри пресета; служит
  проверкой пресета.
- **Словарь** — слова врача → пункт пресета, свой у каждого пресета.

## Решено с заказчиком

1. Каждый пресет хранится в базе отдельно; словарь у каждого пресета свой;
   программа помнит последний выбранный пресет.
2. xlsx — импорт/экспорт пресета. Файл консультации в `diag/` — того же
   формата, просто заполнен с ошибками; импорт должен понятно объяснять ошибки.
3. Правила выбора вариантов должны стать **универсальными** (см. «Способы
   выбора»): видимым свойством группы, а не кодом под активацию.
4. Вид протокола — одна мысль = одна строка, жирные разделы, метка «!» на
   полях для «проверьте». Строки по умолчанию обязательны и верны — обычным
   цветом, без меток. В буфер — чистый текст (поле служебного ПО — простое
   текстовое поле).
5. «Добавить пункт» — строка поиска над протоколом (вариант A); вопрос
   «Каким словом это было в записи?» — в строке статуса, не блокирует; чипы из
   слов записи, выбранное слово подсвечивается в записи; в узком окне —
   6 последних слов и «ещё…».
6. Подсказки в поле записи — в стиле VS Code (IntelliSense): список у курсора
   и серый «хвост», принятие по Tab.
7. Редактор пресетов — визуальный, «как в корпоративном ПО»: дерево слева,
   свойства справа; простой режим для врача, расширенный — для ИТ.
8. Переключатель пресета — по рекомендации дизайн-критика (см. этап 1).
9. «Самолигирующая + лигатуры на нижней» → «…закрытия клипс» (уже в 0.1 beta 3).
10. Порядок работ — последовательно, как в таблице «Этапы».
11. Python — конструктор; в будущем программа может быть переписана на C++/Rust
    (не сейчас). Поэтому логика должна жить в данных (см. «Переносимость»).

## Анти-цели

- Не «корпоративная система»: никаких ролей, сервера, синхронизации. Одна база
  — один врач, обмен — через xlsx.
- Не учиться молча: слово запоминается только после явного выбора врача.
- Не ломать быстрый путь: запись → Ctrl+Enter → вставка работает как сейчас;
  все новые действия необязательны. Enter в записи — перенос строки,
  Ctrl+Enter — сформировать; подсказки их не перехватывают.
- Никаких меток, цветов и служебных символов в буфере.
- Не позволить правке пресета тихо испортить карточки: проверка эталонов перед
  сохранением, отмена изменений.

## Способы выбора (универсальные правила)

Сейчас тип правила угадывается по тексту группы (`_KINDS` в `engine.py`). В 0.2
**способ выбора — свойство группы в пресете**. При импорте xlsx он
проставляется угадыванием, как сейчас (поэтому существующие файлы работают без
правки); в редакторе (этап 5) его видно и можно сменить.

| Способ | Что делает | Сейчас используется для |
|---|---|---|
| По словам записи | вариант, чьи слова есть во фразе о группе | новые группы, жалобы |
| Норма / не норма | «удовлетв/норм» ↔ «неудовл/плох»; «не распознано» → предупреждение | гигиена, слизистая, брекет-система |
| Челюсть | верх / низ / обе из фразы о группе | лигатуры, подвязывание, цепочка |
| Сторона | справа / слева / обе | соотношение моляров и клыков |
| Число | число из фразы (недели; месяцы ×4), ближайший вариант с предупреждением | явка |
| Названия | вариант-название встречается в записи (несколько → предупреждение) | эластики |
| Дуга | размер + материал + челюсть (особый разбор) | смена дуги |
| Класс | I/II/III по молярам/клыкам | соотношения |
| Тип системы / этап | особые словари | тип системы, этап |

Общие для всех способов свойства группы:
- **Когда группа попадает в протокол**: всегда / только если о ней написано.
- **Вариант по умолчанию**, если врач не написал (показывается в списке «по
  умолчанию»).
- **Отрицание** работает везде: «отменён», «без …», «не …».
- Слова группы для упоминания (по умолчанию — собственные слова её текста,
  как в 0.1 beta 3).

Отдельный пункт раздела: «всегда» / «только если в записи есть слово…».

**Правило «всегда» для отдельных пунктов** (решение разработчика): при импорте
пункт получает «всегда», если он есть **больше чем в половине** эталонов пресета
(осмотр, фотопротокол); иначе — «только если упомянут». Без эталонов — «всегда».
В редакторе врач меняет это явно. Причина: разовый пункт, добавленный через
«Добавить пункт» и сохранённый эталоном, не должен пойти во все протоколы.

Переход на способы выбора как данные — **без изменения поведения**: все тесты
0.1 beta 3 и эталоны должны проходить как раньше.

## Переносимость (на будущее C++/Rust)

- Пресеты, эталоны, словарь — в SQLite с описанной схемой (`docs/` — описание
  таблиц), без Python-специфичных форматов (никакого pickle; JSON — только
  простые списки/словари).
- Регрессионные проверки — **данными**: эталоны пресетов + файл реальных
  случаев из диагностики (`tests/cases/*.json`: запись, пресет, ожидаемые коды,
  ожидаемые предупреждения). Python-тесты их читают; будущая реализация на
  другом языке прогоняет те же файлы.
- Логика разбора, специфичная для языка записи (основы слов, раскладка, числа),
  собрана в одном модуле и описана в документе — это то, что придётся
  переписать.

## Этап 1. Пресеты в SQLite, импорт/экспорт, переключатель

### Данные (схема — на разработчике)

- `presets` — id, название, дата создания, источник (файл, sha256, дата импорта),
  «изменён после экспорта».
- `preset_items` — пресет, позиция, код, текст, уровень, родитель; для групп —
  способ выбора, «когда в протоколе», вариант по умолчанию, слова упоминания;
  для отдельных пунктов — «всегда / по упоминанию».
- `reference_cases`, `reference_lines` — эталоны пресета.
- `dictionary` — пресет, слово → **текст** пункта (+ код как подсказка, дата,
  сколько раз сработало). Привязка к тексту: перенумерация не ломает.
- `imports`, `exports` — журнал.
- Существующие `entries`, `settings`, `classifier_snapshots` сохраняются;
  в `entries` добавляется пресет. `PRAGMA user_version` → 2, миграция без потери
  журнала.

Движок продолжает работать с объектом `Workbook` (переименовать можно);
источник — пресет из базы. Проверки файла (`problems`, `warnings`, правила без
групп) — при импорте.

### Импорт

- «Импорт xlsx…» → «Создать новый пресет» (имя по умолчанию — имя файла без
  расширения) или «Обновить пресет «…»».
- Файл с ошибками структуры не импортируется; ошибки — простыми словами, с
  подсказкой, где искать: «не найдена строка заголовка: в колонке A должно быть
  ID_CLASS — проверьте первые строки файла», «строка 7: у кода «1e » лишний
  пробел» и т.п. (сделать на файле `diag/order - kons.xlsx`).
- Обновление **заменяет** пункты и эталоны пресета; словарь сохраняется; если в
  файле есть лист «Словарь», его строки добавляются (одинаковое слово с другим
  пунктом — побеждает файл).
- Если пресет менялся после экспорта (новые эталоны/слова) — перед обновлением
  вопрос «Сначала выгрузить?» (Выгрузить / Обновить без выгрузки / Отмена).
- После импорта — сверка с эталонами, статус «✓ эталоны 2/2».
- **Старые эталоны** переводятся в новый вид автоматически (нужно для этапа 2):
  строка с кодом группы и склеенным текстом («2b | Тип системы вестибулярная
  лигатурная.») → группа + вариант, чей текст совпал со склейкой; строка только
  с кодом варианта → добавляется код группы. Не удалось — строка как есть
  (сверка покажет расхождение).
- Первый запуск 0.2 с базой от 0.1: если в настройках есть путь к файлу и он
  существует — создать из него пресет автоматически (имя — имя файла).

### Экспорт

- «Экспорт xlsx…» выгружает выбранный пресет (имя по умолчанию —
  `<пресет>-ГГГГ-ММ-ДД.xlsx`).
- Первый лист — ровно формат A–F 0.1. Свойства групп, которых нет в формате
  A–F (способ выбора, по умолчанию, «всегда»), — на листе «Настройки» (`Код |
  Способ выбора | Когда в протоколе | По умолчанию | Слова`); при импорте лист
  читается, если есть, иначе свойства угадываются.
- Лист «Словарь»: `Слово | Пункт | Код | Добавлено | Сработало раз`.
- Тест: импорт → экспорт → импорт = тот же пресет.
- Оформление исходного файла (цвета, ширины) не сохраняется — приемлемо.

### Эталоны

«Сохранить как эталон» пишет эталон в базу (нет блокировки Excel и `.bak.xlsx`).
Сверка — после импорта, после сохранения эталона, при запуске, при смене пресета.

### Переключатель пресета (рекомендация дизайн-критика, `presets.html` блок 1)

- Кнопка «Пресет: Активация брекет-системы ▾» (ttk.Menubutton + tk.Menu) на
  месте «Открыть файл…». В меню: список пресетов, «Импорт xlsx…», «Экспорт
  xlsx…», (этап 5) «Изменить пресеты…».
- Имя пресета крупно в шапке окна — чтобы не перепутать тип карточки.
- При смене пресета запись остаётся. Протокол не правили → пересобирается сразу,
  в статусе «Вернуть»; правили → полоса над протоколом «Пересобрать / Оставить
  как есть» (не модально). Буфер при смене не меняется.
- В узком окне — кнопка в первой строке панели, имя пресета в шапке сокращается.

### Диагностика этапа 1

`import`, `export`, `preset_switch`; во всех событиях — пресет (id, имя) вместо
`file`.

## Этап 2. Новый вид протокола

### Склейка (и для окна, и для буфера)

Протокол внутри — список выбранных пунктов (коды); меняется только вывод:

- Заголовок раздела — отдельной строкой.
- Группа + вариант — **одна строка**: «Смена дуги на верхней челюсти
  0.018×0.025" TMA.», «Явка на следующую активацию через 6 недель.».
- Текст варианта уже начинается с текста группы («Тип системы: вестибулярная
  самолигируемая.») — только вариант.
- Варианты-названия — «Назначены межчелюстные эластики: Перепел.»
- Несколько вариантов одной группы (цепочка на обеих) — по строке на вариант.
- Правила стыка (пробел, двоеточие, точка, регистр) — на разработчике; критерий —
  читается как одно нормальное предложение на `diag/order-new-aktiv.xlsx` и
  `order.xlsx`.
- В буфере пустых строк нет. В окне между разделами — отступ тега.

### Сверка эталонов

Сравнивается **набор и порядок кодов** («группа + вариант» всегда, плюс
отдельные пункты и заголовки), а не текст. Строки эталона без кода (свой текст
врача) в сверке не участвуют; «Подробнее» пишет «свои строки врача — N (не
проверяются)». Режимы вывода из эталонов (`join/separate/child_only`)
заменяются склейкой. «Сохранить как эталон» раскладывает склеенную строку на
коды; строку, исправленную врачом так, что она не совпадает ни с одной
склейкой, — пишет без кода.

### Метка «проверьте» («!» на полях)

- На строке, где программа **сама предположила**: сторона класса без
  «справа/слева», дуга на обеих без челюсти, ближайший срок явки, вариант новой
  группы по словам, всё, к чему относится предупреждение.
- Строки по умолчанию не помечаются; список «по умолчанию» под протоколом
  остаётся.
- Под протоколом — оранжевый список причин, каждая с «!».
- Метка — на полях (тег `lmargin`/`lmargincolor` или узкая колонка), не в тексте;
  ручная правка строки снимает метку.

### Буфер

Текст из поля (врач мог править), без меток; форматирование — только теги.

## Этап 3. «Добавить пункт» и словарь

### «Добавить пункт» (`window-variants.html`, вариант A)

- Над протоколом «+ Добавить пункт: начните печатать…» (ttk.Entry), под ним —
  список (Listbox в том же окне, до 7 строк).
- Поиск по вариантам и отдельным пунктам выбранного пресета, без учёта
  регистра и раскладки; группа и раздел — серым справа («Лечение → Юстировка
  дуги»), сами не выбираются. Подсвечивается только набранное; кода нет.
- Ранжирование: совпадение с начала слова выше; уже добавлявшиеся врачом выше.
- ↑↓, Enter — добавить, Esc — закрыть.
- Пункт встаёт в свой раздел, на своё место; другой вариант той же группы
  заменяется. **Ручные правки сохраняются**: вставка в текущий текст после
  последней строки раздела (раздел — по строке-заголовку); заменяемая строка
  убирается, только если не изменена; нет заголовка — раздел добавляется на
  своё место.
- Подсветка добавленной строки 3 секунды; протокол сразу заново копируется;
  статус «✓ Добавлено: Изгиб третьего порядка → Лечение. Протокол скопирован.»

### Непонятые слова в записи (из разбора ТРИЗ)

- Разбор отмечает, какие слова записи он использовал. После Ctrl+Enter
  слова, которые не использовало ни одно правило и ни одно слово словаря,
  подчёркиваются в записи пунктиром (тег, в текст не входит). Служебные слова
  («на», «и», «по», «с», числа, разделители) не подчёркиваются; список
  служебных — на разработчике.
- Подсказка при наведении: «программа не поняла это слово».
- Правка записи снимает подчёркивание до следующего Ctrl+Enter.

### Вопрос «Каким словом это было в записи?»

- В статусе сразу после добавления; ничего не блокирует.
- **Кандидат выбран заранее** (из разбора ТРИЗ): непонятое слово записи,
  ближайшее по смыслу к добавленному пункту (если непонятое одно — оно);
  вопрос звучит «Это было «торк»? [Да] [Другое слово…] [Пропустить]».
  «Да» — одно нажатие. Нет непонятых слов — вопрос как ниже, без кандидата.
- Чипы — слова записи (в узком окне 6 последних и «ещё…»); выделение мышью
  фразы в записи → «Запомнить «18х25 тма»».
- Выбранное слово подсвечивается в записи.
- «Запомнить» → словарь пресета; «Запомнено: торк → Изгиб третьего порядка» +
  «Отменить». «Пропустить» — ничего. Новая генерация убирает вопрос.

### Словарь в разборе записи

- Слово найдено в записи (по основе, с учётом раскладки) и не отменено → пункт
  выбран; для варианта — в своей группе вместо правила; для отдельного пункта —
  включён.
- Словарь — **раньше** правил. Строка по словарю — без «!».
- Пункт слова исчез (после обновления пресета) — оранжевое «слово «торк»
  больше не находит пункт»; слово не удаляется.
- Счётчик «сработало раз».

### Диагностика этапа 3

`add_item`, `learn`, `learn_undo`, `learn_skip`; в `generate` — сработавшие
слова словаря.

## Этап 4. Подсказки в записи (`presets.html` блок 3, вариант IntelliSense)

- Список у курсора: слова словаря пресета и слова пунктов; справа серым — во что
  превратится («торк → Изгиб третьего порядка»). Появляется с 3-й буквы;
  выключатель в настройках.
- Первый пункт обведён, но не выделен: **Tab** принимает его; Enter — перенос
  строки, пока не нажата ↓; Ctrl+Space — вызвать вручную; Esc — закрыть.
  Ctrl+Enter не перехватывается.
- Лучший вариант — серым «хвостом» после курсора (метка поверх текста, не
  вставка — чтобы не ломать undo и `get()`).
- Вставляется слово врача, а не текст пункта.
- Список — рамка внутри того же окна через `place()` по `bbox('insert')`, не
  Toplevel; у нижнего края — разворачивается вверх; при прокрутке, смене размера,
  потере bbox — закрывается.

## Этап 5. Редактор пресетов (`presets.html` блок 2, вариант дерево + свойства)

**Контрольная точка перед этапом** (из разбора ТРИЗ): по диагностике этапов 1–4
посчитать, какие правки логики пресета врачу понадобились на деле. Если почти
все закрываются словарём и листом «Настройки» в xlsx — редактор упростить
(например, только свойства групп без правки структуры). Решение — с заказчиком.

- Отдельное окно: PanedWindow, слева Treeview «раздел → группа → вариант /
  отдельный пункт», справа — свойства выбранного.
- Действия со структурой: добавить, удалить, переименовать, переставить
  (кнопками ↑↓ — перетаскивания в Treeview нет), коды — автоматически.
- Свойства группы (простой режим): «Как выбирать вариант» — способы выбора
  простыми словами с примером; «если врач не написал → по умолчанию»; «когда в
  протоколе»; слова врача (список, удалить); предпросмотр строки; плашка
  «пункт есть в N эталонах из M».
- Отдельный пункт: «всегда» / «только если в записи есть слово…».
- Вкладка «Эталоны»: список, ✓/✗, расхождение «было… стало…».
- «Проверить на записи»: поле записи → протокол по редактируемому пресету.
- **Защита**: правки — черновиком (транзакция/копия пресета) до «Сохранить»;
  перед сохранением обязательная сверка эталонов с показом изменений; отмена
  (свой стек команд); «Отменить изменения».
- Переключатель **Простой | Расширенный**. Расширенный добавляет: коды, способ
  склейки, тип правила напрямую, шаблоны поиска (регулярные выражения),
  приоритет, журнал срабатываний, словарь «как есть».
- Пресеты: новый, копировать, переименовать, удалить (с подтверждением),
  импорт/экспорт.

## Разбор ТРИЗ (кратко)

ИКР: протокол появляется из записи сам, без ошибок; программа учится без
разработчика и без лишних действий врача.

| Противоречие | Приём | Решение |
|---|---|---|
| Строки должны быть (шаблон) и не должны (додуманные процедуры) | разделение по условию | шаблон/по умолчанию — всегда, процедуры — по словам записи |
| Пометки нужны врачу, но не карточке | разделение в пространстве | «!» на полях, буфер — чистый текст |
| Свободная запись быстра, но неточна | посредник | подсказки по Tab |
| Редактор прост и мощен | разделение по условию | простой/расширенный режим |
| Врач правит логику, но карточки не должны ломаться | разделение во времени | черновик → сверка эталонов → сохранение |
| Python сейчас, C++/Rust потом | предварительное действие | логика и проверки — в данных |

Неиспользованные ресурсы: разбор знает непонятые слова → подчёркивание и
кандидат для вопроса «каким словом» (этап 3); диагностика → контрольная точка
перед редактором (этап 5).

## Ограничения

- Только tkinter/ttk + sv-ttk; без новых тяжёлых зависимостей.
- Сборка, версия, диагностика — как в 0.1 (build.ps1, портативная + один exe).
- Тесты на каждый этап; реальные записи из диагностики — регрессионные данные.

## Решения разработчика (проверьте при чтении)

- Старые эталоны переводятся в новый вид автоматически при импорте.
- Строки эталона без кода в сверке не участвуют (счётчик в «Подробнее»).
- «Добавить пункт» сохраняет ручные правки врача.
- Добавить и привязать слово можно только к варианту или отдельному пункту.
- «Всегда» для отдельного пункта — если он больше чем в половине эталонов.
- Свойства групп, которых нет в A–F, экспортируются на лист «Настройки».
- Словарь при обновлении пресета сохраняется; «Словарь» из файла дополняет его.

## Оставлено разработчику

Схема таблиц и миграция; правила стыка; отрисовка «!»; ранжирование поиска;
длительности подсветок; внутреннее устройство отмены в редакторе.
