# Orthofill 0.2 beta 4–5: редактор пресета, коды, проверка классификатора, логика полей

Дата: 22.10.2026. Продолжает `2026-10-21-orthofill-0.2-design.md` (этапы 4 и 6
объединены и пересобраны по разговору 22.10). Экраны — вариант A дизайн-критика
(`.superpowers/brainstorm/2866305-1792601460/content/presets.html`, блок 2).

## Зачем

Пресет приходится править: добавить новые значения в классификатор, убрать
повторы, проверить и исправить ID_CLASS. Сейчас для этого — экспорт xlsx, найти
файл в каталоге, Excel, импорт обратно. Мучает именно этот круг, а не Excel.

Два языка пресета (слова заказчика):

- **xlsx — разговор с врачом.** Наглядная таблица, по которой врач понимает,
  как оформить пресет. JSON/XML для врача — непреодолимы. Импорт/экспорт
  остаются и переносят всё новое (без потерь по кругу).
- **Редактор в программе — для ИТ-специалиста (и врача в простом режиме).**
  Как в медицинском ПО: дерево и поиск по нему.

Каркас на будущее (C++/Rust): **бизнес-логика — декларативно в данных пресета**
(структура, коды, сочетание, условия, умолчания, словарь); в коде — интерпретатор
и небольшая библиотека распознавателей ортодонтической записи (`methods.py`:
размер дуги, челюсть из фразы, срок, сторона, «без …»). Эталоны и
`tests/cases/*.json` — проверка совместимости будущей реализации.

## Найдено в данных врача (`diag/`, не в репозитории)

- Повторов кодов нет.
- «на верхней челюсти.» — 4d1, 4e1, **4p2**; «на нижней челюсти.» — 4d2, 4e2,
  **4p1**: в группе p порядок челюстей обратный (ошибка ID_CLASS).
- Одинаковый текст вариантов разных групп сам по себе не ошибка: в протоколе
  строки склеиваются с группой и различаются.

## Цели

1. Править пресет, не выходя из программы: структура, тексты, коды, свойства.
2. Коды ID_CLASS — внутренние; менять их свободно, **эталоны и словарь
   переписываются сами**.
3. Программа сама показывает ошибки классификатора.
4. (beta 5) Логика сочетания пунктов — И / ИЛИ / НЕ / И-НЕ — в данных, не в коде.

## Не цели

- Перетаскивание мышью в дереве (только ↑↓).
- Склейка, приоритеты, регулярные выражения, «последние 20 срабатываний» из
  расширенного режима критика — нет в модели данных; позже, если понадобятся.
- Подсказки в записи по Tab — следующий этап (после beta 5).
- Несколько пользователей / права доступа.

## Анти-цели (провал, даже если «работает»)

- Правка пресета молча ломает эталоны или словарь врача.
- Условия **добавляют** в протокол то, чего не было в записи. Условие может
  только запретить строку; челюсть и прочее — только из записи; противоречие —
  показать («проверьте»), не исправлять.
- Врач в простом режиме видит коды, JSON, служебные слова.
- Несохранённые правки теряются без вопроса при закрытии окна.

## Ограничения

- tkinter/ttk + sv-ttk, Treeview; без новых зависимостей.
- Windows 11, портативная сборка, `build.ps1`; версия, журнал изменений
  (`CHANGELOG.md`, тест «верхний раздел = версия»), диагностика — как раньше.
- Схема базы: beta 4 — без изменений (v2: `method`, `when_`, `default_code`,
  `words_json` уже есть); beta 5 — v3 с миграцией.
- Каждое решение пересказывается в `docs/presets-schema.md` (для переноса).
- TDD; реальные записи из диагностики — регрессионные данные.

## Выпуск 0.2 beta 4 — редактор, коды, проверка

### Окно редактора

Отдельное немодальное окно (Toplevel), одно на программу. Входы:

- «Пресет: … ▾» → «Изменить пресет…»;
- правый щелчок по строке протокола → «Изменить «<пункт>» в пресете…» —
  редактор открывается на этом пункте (код строки — `Row.codes`; у строки
  «группа + вариант» — вариант). Свой текст врача (без кода) — пункта меню нет.

Сверху: имя пресета, переключатель **Простой | Расширенный** (запоминается в
настройках), «Импорт xlsx…», «Экспорт xlsx…». Вкладки: **Пункты протокола**,
**Эталоны (N)**, **Слова врача (N)**, **Проверка (N)**.
Внизу всегда: «↶ Отменить», «↷ Вернуть», «● Изменено: N, не сохранено»,
«Проверить эталоны», «Отменить изменения», «Сохранить».

### Вкладка «Пункты протокола»

Слева: поле поиска + дерево «раздел → группа → вариант / отдельный пункт» в
порядке протокола. Поиск — `addition.search_items` (начала слов, любая
раскладка, размеры дуг); найденное выделяется и раскрывается, ↑↓ / Enter — по
результатам. У узлов — значки: ● по умолчанию, «всегда», ⚠ находка проверки.
В расширенном режиме — колонка кода.

Под деревом: «+ Пункт», «+ Вариант», «↑», «↓», «Удалить».

- Новый пункт/вариант получает следующий свободный код (буква группы /
  номер варианта), встаёт после выделенного; сразу открывается правка текста.
- ↑↓ — в пределах родителя; меняет порядок вывода, код не меняется.
- Удалить — подтверждение; если пункт есть в эталонах или словаре — сказать
  сколько («есть в 2 эталонах и 1 слове врача»). Удаление группы — с вариантами.

Справа — свойства выделенного (простой режим, слова врача):

| Узел | Поля |
|---|---|
| Раздел | Название |
| Группа | Название; «Как выбирать вариант» (`METHOD_LABELS`, подпись и пример); «Если врач не написал»: вариант по умолчанию ▾ / не выводить |
| Вариант | Текст; ☐ по умолчанию |
| Отдельный пункт | Текст; «Когда в протоколе»: всегда / если упомянут |
| Все | Слова упоминания (список, + / удалить); слова врача, привязанные к пункту (удалить); «Так будет в протоколе» (`render.join_group`); плашка «есть в N эталонах из M» |

Расширенный режим добавляет: поле **Код** (правка — см. «Коды»); ключ способа
выбора как есть; «угадано» / «задано» у способа и «когда»; «Перенумеровать по
порядку» (у раздела и группы); число срабатываний слов врача.

### Коды ID_CLASS

Код кодирует место: раздел `4`, группа/пункт `4b`, вариант `4b7`. Правило:

- Правка кода в расширенном режиме: формат (`_CODE_RE`), уникальность, тот же
  уровень, родитель с таким кодом существует. Смена родительской части кода =
  перенос пункта в другую группу/раздел (вариант `4p1` → `4d3`).
- Смена кода группы/раздела переименовывает коды детей (`4p` → `4q`: `4p1` →
  `4q1`).
- «Перенумеровать по порядку»: варианты группы — 1, 2, 3… по текущему порядку;
  группы раздела — a, b, c…
- **Каскад** при любой смене кода (одна таблица «старый → новый» на правку):
  `default` групп, коды строк эталонов (`reference_lines.code`), коды словаря
  (`DictEntry.code`). Смена текста пункта переписывает `DictEntry.item_text`.
  Журнал (`entries`) не трогается — там текст.
- Обмен кодами (4p1 ↔ 4p2) — одной правкой: «Перенумеровать» или правка кода
  на занятый в пределах той же группы предлагает «Поменять местами?».

### Проверка классификатора (вкладка «Проверка», значки ⚠ в дереве)

Функция над данными (без окна), список находок `(код, вид, текст)`:

| Вид | Что | Уровень |
|---|---|---|
| повтор строки | одинаковый текст **строки протокола** (после склейки с группой) у двух пунктов | ошибка |
| повтор в группе | два варианта одной группы с одинаковым текстом | ошибка |
| порядок челюстей | в группе варианты «верхн»/«нижн» стоят в обратном порядке относительно большинства групп пресета | предупреждение |
| пропуск номера | у вариантов группы пропущен номер (4b1, 4b3) | сведение |
| нет умолчания | группа «всегда в протоколе» без варианта по умолчанию | сведение |
| пустая группа | группа без вариантов | предупреждение |

Щелчок по находке — выделить пункт в дереве. Те же находки — в «Подробнее»
главного окна (заменяют нынешнее «одинаковый текст у …», которое ругается и на
допустимые повторы).

### Черновик, отмена, сохранение

- Редактор работает с копией пресета (`Workbook`) в памяти. Каждая правка —
  команда; «Отменить / Вернуть» — по командам (ок — снимок копии на команду:
  пресет ~200 пунктов).
- «Проверить эталоны» — `check_references` по черновику; вкладка «Эталоны»:
  ✓/✗ у каждого, у ✗ — «было … стало …» построчно; «Принять новое как эталон»,
  «Удалить эталон».
- «Сохранить»: если проверка не запускалась или есть ✗ — вопрос с числом
  сломанных эталонов. Запись — одной транзакцией (`PresetStore`, как `update`,
  но без записи в `imports`; пресет помечается `dirty` — есть то, чего нет в
  выгруженном xlsx).
- Закрытие окна с несохранённым — «Сохранить / Не сохранять / Отмена».
- После сохранения главное окно пересобирает протокол без копирования в буфер
  (как при смене пресета, с «Вернуть»).
- Событие диагностики `preset_saved`: сколько пунктов добавлено / удалено /
  изменено, таблица смены кодов, итог проверки эталонов.

### Решения по проверке описания (решения исполнителя, 22.10; заказчик может поправить)

1. **Главное окно пишет в пресет, пока открыт редактор** (выучено слово,
   сохранён эталон). «Сохранить» в редакторе записывает **пункты** из черновика,
   а эталоны и словарь берёт **текущие из базы**, повторяет на них действия
   вкладок редактора (удалить / принять эталон, удалить слово) и применяет
   каскад кодов и текстов. Так ничто, добавленное в главном окне, не теряется.
   Импорт xlsx поверх этого же пресета в главном окне при несохранённом
   черновике — вопрос «Пресет открыт в редакторе с несохранёнными правками».
   Смена пресета в главном окне редактор не трогает: он привязан к своему
   пресету (имя в заголовке).
2. **Смена текста пункта** переписывает и строки эталонов, чей текст совпадал
   со старой строкой протокола этого пункта (иначе они стали бы «формулировкой
   врача» и проверяли бы меньше). Строки со своим текстом врача не трогаются.
3. **Удаление пункта**: строки эталонов с его кодом становятся строками без
   кода (своими строками врача) — эталон честно покажет ✗, на вкладке
   «Эталоны» можно принять новое; слова врача, привязанные к пункту,
   удаляются. Всё это — в подтверждении («есть в 2 эталонах и 1 слове врача»)
   и отменяется вместе с удалением.
4. **«Порядок челюстей»** читает номера кодов, а не порядок вывода (это ошибка
   ID_CLASS); ↑↓ её не снимает. Исправление в находке — «Поменять коды
   местами» (одна команда с каскадом).
5. **Импорт xlsx в редакторе** — одна отменяемая команда над черновиком
   (заменяет пункты, эталоны и слова — как `update`; дальше «Проверить
   эталоны» и «Сохранить»). **Экспорт** — только сохранённой версии; при
   несохранённом черновике — «Сначала сохранить?». Флаги `dirty` /
   `mark_exported` — как сейчас, от сохранённой версии.
6. **Угаданные настройки при правке текста.** Способ выбора и «когда» угадываются
   по тексту (`engine.guess_settings`). Перед правкой текста группы/пункта
   редактор **закрепляет** текущее угаданное значение как заданное (в той же
   команде), чтобы переименование не меняло поведение молча. Остальные пункты
   остаются угадываемыми. Правила по кусочку текста (`_orphan_applies`,
   `rule_warnings`) до beta 5 могут сработать иначе после переименования —
   это ловит «Проверить эталоны»; в «Так будет в протоколе» видно сразу.

### Вкладка «Слова врача»

Таблица: слово → пункт (текст, в расширенном — код), когда добавлено, сколько
раз сработало; удалить; переход к пункту в дереве.

### Изменения в главном окне

- Меню «Пресет ▾»: + «Изменить пресет…».
- Правый щелчок по строке протокола — меню (см. «Окно редактора»).
- «Подробнее» — находки проверки классификатора.

## Выпуск 0.2 beta 5 — логика полей (И / ИЛИ / НЕ / И-НЕ)

Подробности экрана условий — дизайн-критик до плана beta 5.

| | Где | Смысл | Пример |
|---|---|---|---|
| **И** | группа / раздел | пункты совместимы: каждый выводится сам (всегда / если упомянут / если условие) | 3a внешний осмотр, 3b ВНЧС, 3c лимфоузлы |
| **ИЛИ** | группа | ровно один вариант (как сейчас любая группа) | 4c смена дуги на нижней: 4c1, 4c2… |
| **НЕ** | пункт, «Условие» | показывать, если НЕ [поле = значение] | лигатуры — если система НЕ самолигирующая |
| **И-НЕ** | пара пунктов, «Не вместе с» | не могут быть вместе; если в записи оба — обе строки и предупреждение «проверьте», программа не выбирает | клипсы ↔ фиксация лигатурами |

- «Сочетание» (И / ИЛИ) — свойство группы; по умолчанию ИЛИ (как сейчас).
  Группа И: варианты выводятся все, которые упомянуты (межчелюстные эластики —
  два вида сразу).
- «Когда в протоколе» у пункта: всегда / если упомянут / **если условие**.
  Условие — строки «[поле] = [значение]» или «[поле] упомянуто», между ними
  И / ИЛИ, у строки — НЕ; поля и значения выбираются из дерева пресета.
  Условие **только сужает**: строка «если упомянут + условие» не появляется без
  упоминания.
- Зашитые в коде правила по кусочку текста (`engine._orphan_applies`: клипсы /
  фиксация лигатурами) переезжают в условия; поведение на эталонах и
  `tests/cases` не меняется.
- Хранение: схема v3 — у пункта `combine` (`and`/`or`), `condition_json`
  (дерево `{"all"|"any": [...], "not": …, "field": код, "is": код варианта |
  "mentioned"}`), `not_with_json` (список кодов). xlsx: лист «Настройки» —
  столбцы «Сочетание», «Условие» (читаемо, с кодами: `2a = 2a1 И НЕ 4e`),
  «Не вместе с». Экспорт ↔ импорт без потерь.
- Проверка классификатора: повтор в группе — ошибка только для ИЛИ; условие
  ссылается на несуществующий код — ошибка.
- Позже (не beta 5): предупреждения вида «класс без моляров/клыков» —
  условия с действием «предупредить».
