# Orthofill 0.5 beta 2 — предсказание в оболочке: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оболочка предсказывает: на пустой строке серым — следующая строка (привычка врача, соседи группы «И», дальше по порядку файла); в списках частые у врача варианты — сверху и уже выбраны; история врача (строки-пути и подтверждённые записи через запятую) даёт частоты и переходы.

**Architecture:** `orthofill/pathstats.py` без Tk: статистика путей врача по журналу (частоты пунктов, переходы «после этой строки — эта», первая строка), кэш в контроллере. `orthofill/predict.py` без Tk: порядок вариантов (`rank`) и кандидаты следующей строки (`predict`). `ShellBox` показывает предсказание серым на пустой строке, Tab/Ctrl+→ принимают, `?` — список кандидатов.

**Tech Stack:** Python 3.12, tkinter, sqlite3, pytest.

**Spec:** `docs/superpowers/specs/2026-10-22-orthofill-0.5-shell-design.md` — «Уровни и предсказание», «Переход», «Решения заказчика» п. 7, «Анти-цели»; план 0.5 b1 — `docs/superpowers/plans/2026-10-22-orthofill-0.5b1-shell.md`.

## Global Constraints

- **Порядок файла задаёт направление** (заказчик): кандидаты следующей строки — узлы **после** последней строки (её группы) в порядке `wb.items`, затем — остальные; уже записанные в этой записи группы/пункты пропускаются.
- **Родитель известен**: после листа группы «И» (`combine == 'and'`) первыми — её ещё не выбранные варианты; после «ИЛИ» соседей не предлагать.
- **Привычка**: переход «после пункта A — пункт B», встретившийся у врача ≥ 2 раз, идёт первым (до порядка файла). Первая строка записи — самая частая первая строка (≥ 2), иначе первый по файлу узел, который врач хоть раз писал, иначе первый по файлу.
- **Частота поднимает**: в любом списке оболочки пункты с частотой ≥ 2 — сверху по убыванию, остальные — порядок файла; список, открытый Tab/`?` по уровню, выделяет первый.
- **Источники статистики**: строки-пути оболочки (точно); записи через запятую — **только подтверждённые** (`copied_text` не пуст): пункты протокола этой записи, которых нет в протоколе пустой записи (то, что врач сказал, а не умолчания), в порядке протокола.
- Предсказание **никогда не вставляет текст само**: только серая подсказка; набор буквы её убирает.
- Пустая строка: серым `→ <путь>` (до группы с ` › …` или до листа, если привычка — лист); **Tab** — принять целиком (на группе — сразу список веток с частым выделенным), **Ctrl+→** — один уровень, **`?`** — список кандидатов (до 12).
- Телеметрия: `shell` `predict` с `outcome` `accepted|level|ignored` и `source` `habit|and|file|first`.
- Версия `0.5.0b2` / «0.5 beta 2»; `CHANGELOG.md` «0.5 beta 2».

## Review Focus

1. Врач пишет строки не по порядку файла (сначала «Лечение», потом «Анамнез») — предсказание идёт от **последней строки над курсором**, уже записанное не предлагается (Task 2 `test_predict_after_out_of_order`).
2. Курсор на пустой строке **в середине** записи — предсказание от строки над ним, не от конца записи (Task 3 `test_predict_middle_line`).
3. Пункт удалён из пресета, а в истории он есть — статистика его пропускает, без падения (Task 1 `test_stats_skip_missing_codes`).
4. Журнал на 2000 записей — статистика считается один раз (кэш), набор не тормозит: `predict` + `rank` < 20 мс (Task 1 `test_stats_cached`, Task 2 `test_predict_fast`).
5. Серая подсказка не попадает в текст при наборе, Enter на пустой строке с подсказкой — обычный перенос (Task 3 `test_typing_dismisses_prediction`, `test_enter_ignores_prediction`).
