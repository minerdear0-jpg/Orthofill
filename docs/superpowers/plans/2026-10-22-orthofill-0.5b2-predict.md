# Orthofill 0.5 beta 2 — предсказание в оболочке: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оболочка предсказывает: на пустой строке серым — следующий по файлу пункт из **обычного набора** врача; в списках частые у врача варианты — сверху и уже выбраны. Порядок не угадывается — его задал врач в xlsx (заказчик: «идеальный конечный результат врач уже задал в пресете — порядок мы знаем, меняется только набор полей»); история (строки-пути и подтверждённые записи через запятую) даёт только **набор**: какие пункты врач обычно пишет и какие варианты выбирает.

**Architecture:** `orthofill/pathstats.py` без Tk: набор врача по журналу (в скольких записях встречался каждый пункт), кэш в контроллере. `orthofill/predict.py` без Tk: порядок вариантов (`rank`) и кандидаты следующей строки (`predict`). `ShellBox` показывает предсказание серым на пустой строке, Tab/Ctrl+→ принимают, `?` — список кандидатов.

**Tech Stack:** Python 3.12, tkinter, sqlite3, pytest.

**Spec:** `docs/superpowers/specs/2026-10-22-orthofill-0.5-shell-design.md` — «Уровни и предсказание», «Переход», «Решения заказчика» п. 7, «Анти-цели»; план 0.5 b1 — `docs/superpowers/plans/2026-10-22-orthofill-0.5b1-shell.md`.

## Global Constraints

- **Порядок — только файл врача** (заказчик): кандидаты следующей строки — узлы **после** последней строки над курсором в порядке `wb.items`, по кругу до неё; переходов «после A — B» нет. Уже записанные в этой записи группы/пункты пропускаются.
- **Набор — из истории**: «обычный» узел — встречался не меньше чем в `USUAL = 0.3` доли учтённых записей и не меньше 2 раз. Серая подсказка — **первый обычный** узел по файлу после последней строки (нет обычных — первый по файлу); список `?` — все кандидаты по файлу, обычные помечены «★».
- **Родитель известен**: после листа группы «И» (`combine == 'and'`) первыми — её ещё не выбранные варианты, если они обычны; после «ИЛИ» соседей не предлагать.
- Первая строка записи — первый обычный узел по файлу (нет истории — первый по файлу).
- **Частота поднимает**: в любом списке оболочки пункты с частотой ≥ 2 — сверху по убыванию, остальные — порядок файла; список, открытый Tab/`?` по уровню, выделяет первый.
- **Источники статистики**: строки-пути оболочки (точно); записи через запятую — **только подтверждённые** (`copied_text` не пуст): пункты протокола этой записи, которых нет в протоколе пустой записи (то, что врач сказал, а не умолчания), в порядке протокола.
- Предсказание **никогда не вставляет текст само**: только серая подсказка; набор буквы её убирает.
- Пустая строка: серым `→ <путь>` (до группы с ` › …` или до листа, если привычка — лист); **Tab** — принять целиком (на группе — сразу список веток с частым выделенным), **Ctrl+→** — один уровень, **`?`** — список кандидатов (до 12).
- Телеметрия: `shell` `predict` с `outcome` `accepted|level|ignored` и `source` `usual|and|file`.
- Версия `0.5.0b2` / «0.5 beta 2»; `CHANGELOG.md` «0.5 beta 2».

## Review Focus

1. Врач пишет строки не по порядку файла (сначала «Лечение», потом «Анамнез») — предсказание идёт от **последней строки над курсором** по кругу, уже записанное не предлагается; протокол всё равно в порядке файла (Task 2 `test_predict_after_out_of_order`).
2. Курсор на пустой строке **в середине** записи — предсказание от строки над ним, не от конца записи (Task 3 `test_predict_middle_line`).
3. Пункт удалён из пресета, а в истории он есть — статистика его пропускает, без падения (Task 1 `test_stats_skip_missing_codes`).
4. Журнал на 2000 записей — статистика считается один раз (кэш), набор не тормозит: `predict` + `rank` < 20 мс (Task 1 `test_stats_cached`, Task 2 `test_predict_fast`).
5. Серая подсказка не попадает в текст при наборе, Enter на пустой строке с подсказкой — обычный перенос (Task 3 `test_typing_dismisses_prediction`, `test_enter_ignores_prediction`).

### Task 1: Статистика путей врача (`pathstats.py`)

**Files:** Create `orthofill/pathstats.py`; Modify `orthofill/journal.py` (`entries_for_stats(preset_id, limit=2000) -> list[tuple[str, str | None]]` — `(raw, copied_text)`), `orthofill/controller.py` (`path_stats() -> PathStats`, кэш по `(preset_id, wb.sha256, число записей)`); Test `tests/test_pathstats.py`.

**Interfaces:**
- Produces: `PathStats(count: dict[str, int], notes: int)` — `count[код]` — в скольких учтённых записях был пункт (лист, его группа и раздел тоже считаются), `notes` — сколько записей учтено; `PathStats.usual(code) -> bool` (по `USUAL`); `build_stats(wb, entries: list[tuple[str, str | None]]) -> PathStats`; `note_codes(wb, raw: str, copied: str | None) -> list[str]` — коды листов записи по порядку (строки-пути — `parse_line`; запись через запятую — только если `copied`, листы её протокола минус листы протокола пустой записи).

- [ ] **Step 1: tests** — `test_shell_lines_counted` (2 записи-пути 2b2, 4b5 → `count['4b5'] == 2`, `count['4b'] == 2`, `notes == 2`, `usual('4b5')`; пункт, бывший в 1 из 5 записей, — не обычный); `test_comma_only_confirmed` (запись «лигатурная, перепел» без `copied` — не учтена; с `copied` — учтён `4f1`, умолчания (`2c2`) — нет); `test_stats_skip_missing_codes` (строка-путь к удалённому пункту — пропущена); `test_stats_cached` (два вызова `ctl.path_stats()` без новых записей — один пересчёт: `build_stats` подменён счётчиком; после `generate` — пересчёт).

### Task 2: Порядок и кандидаты (`predict.py`)

**Files:** Create `orthofill/predict.py`; Test `tests/test_predict.py`.

**Interfaces:**
- Consumes: Task 1 `PathStats`; 0.5 b1 `shell.children_of`, `is_leaf`, `Path`.
- Produces: `rank(paths: list[Path], stats: PathStats) -> list[Path]` (варианты внутри уровня: частые сверху, стабильно); `Prediction(path: Path, source: str, usual: bool)`; `predict(wb, note_paths: list[Path], stats: PathStats, limit: int = 12) -> list[Prediction]` — `note_paths` — готовые строки **выше курсора** по порядку; кандидаты по файлу после последней (по кругу), обычные «И»-соседи — первыми; **первый элемент** — первый обычный (или первый по файлу без истории); кандидат — путь до группы (если у неё варианты) или до пункта; без уже записанных групп/пунктов, без «нет».

- [ ] **Step 1: tests** — `test_rank_frequent_first` (`count` 4b5=5, 4b18=2, 4b2=1 → 4b5, 4b18, затем 4b1… по файлу); `test_first_line_usual` (история: 2b в 5 из 5 записей, 1a-раздел жалоб не писали → первый кандидат `('2','2b')`, source `usual`); `test_first_line_file_order_without_history`; `test_after_leaf_next_group_by_file` (после 2b2 без истории → `('2','2c')`, source `file`); `test_skips_unusual` (после 2b2: 2c — в 0 из 5, 4b — в 5 из 5 → первый 4b, source `usual`; 2c в списке есть, без «★»); `test_and_siblings_first` (группа 4g c `combine='and'`, после 4g1 → 4g2, source `and`); `test_or_no_siblings` (после 4f1 → не 4f2); `test_predict_after_out_of_order` (строки 4b5, затем 2b2 → первый кандидат после 2b по файлу (2c), группы 4b и 2b не предлагаются); `test_predict_fast` (2000 записей статистики, 100 вызовов `predict`+`rank` < 2 с).
