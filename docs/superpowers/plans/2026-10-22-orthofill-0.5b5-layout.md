# Orthofill 0.5 beta 5 — оболочка на всю ширину, отчёт по требованию: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** В режиме «Оболочка» поле записи занимает всё окно; живой протокол выезжает поверх справа по F2 (выдвижная панель, вариант B); на финале — Ctrl+Enter — окно делится для сравнения: слева запись, справа протокол (вариант C). Заказчик 22.10: «область справа неэффективна, нужен максимум пространства для ввода; B, но комбинировано с C — появляется на финале, когда нужно сравнить данные».

**Architecture:** Раскладка тела окна в режиме оболочки — одно из трёх состояний `App.shell_view`: `input` (только запись, протокол скрыт), `drawer` (запись на всю ширину + протокол поверх справа `place`), `review` (две колонки `grid`: запись | протокол). Режим «через запятую» — прежняя раскладка (`_relayout` wide/narrow) без изменений. Протокол — тот же виджет (`out_panel`/`out_txt`), холст 0.5 b3 работает во всех состояниях.

**Tech Stack:** Python 3.12, tkinter, pytest.

**Spec:** решение заказчика 22.10 (Goal); `docs/superpowers/specs/2026-10-22-orthofill-0.5-shell-design.md` — «Холст протокола»; мокап `.superpowers/brainstorm/…/layout-report.html` (B и C).

## Global Constraints

- Только режим «Оболочка». Режим «через запятую» — как раньше.
- `input` — по умолчанию: запись на всю ширину тела окна; у правого края — ярлык «Протокол ◂ F2» (узкая кнопка), щелчок = F2.
- **F2** — `input` ↔ `drawer`: панель протокола поверх правых 46 % тела окна (в узком окне — 100 %), с тенью-рамкой; фокус остаётся в записи; набор продолжается. Esc в записи при открытой панели — закрыть (если нет открытого списка оболочки — у него Esc свой).
- **Ctrl+Enter** — как сейчас подтверждает и копирует (решение исполнителя: без лишнего нажатия), и переводит в `review`: две колонки (запись 55 % | протокол 45 %; в узком окне — протокол под записью), протокол — тот, что скопирован, со своим текстом врача.
- Из `review` в `input`: Esc (в любом поле) или первый набор в записи. Правка в протоколе справа и повторный Ctrl+Enter — копирует исправленное (как сейчас), `review` остаётся.
- Состояние не сохраняется между запусками (всегда `input`); ширина 46 %/55 % — константы `DRAWER_W = 0.46`, `REVIEW_SPLIT = 0.55`.
- Телеметрия: `ui` `name='drawer_open'|'drawer_close'|'review_open'|'review_close'` (без текста).
- Версия `0.5.0b5` / «0.5 beta 5»; `CHANGELOG.md` «0.5 beta 5». План «Ошибка → Исключить» — 0.5 beta 6.

## Review Focus

1. Переключение режима «Оболочка» туда-обратно возвращает прежнюю раскладку через запятую (wide/narrow) без остатков панели (Task 1 `test_comma_layout_restored`).
2. Открытая панель не перехватывает набор: фокус в записи, буквы идут в запись, оболочка подсказывает (Task 1 `test_drawer_keeps_focus`).
3. Esc с открытым списком оболочки закрывает список, а не панель; второй Esc — панель (Task 1 `test_escape_order`).
4. Узкое окно (< 900 px): панель и проверка не выходят за край, протокол виден целиком по ширине (Task 1 `test_narrow_window`).
5. Ctrl+Enter в `review` после правки протокола копирует правку, не сворачивая проверку (Task 2 `test_review_recopy_edit`).
