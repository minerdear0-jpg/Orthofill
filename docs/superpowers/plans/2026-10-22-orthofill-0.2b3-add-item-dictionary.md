# Orthofill 0.2 beta 3 — «Добавить пункт», словарь врача, непонятые слова. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** врач добавляет пропущенный пункт поиском над протоколом, одним нажатием учит программу своему слову («торк → Изгиб третьего порядка»), и в следующий раз слово понимается само; непонятые слова записи подчёркиваются сразу после Ctrl+Enter.

**Architecture:** словарь пресета (таблица `dictionary`, есть с 0.2b1) применяется в `build_protocol` **до** правил: слово врача выбирает вариант своей группы или включает отдельный пункт (`ctx.forced`). Непонятые слова — новый модуль `vocab.py`, **самопроверкой** (ТРИЗ): слово «понято», если без него меняется протокол, если оно есть в текстах пресета или в словаре; ручного списка основ нет. Вставка пункта в правленый текст — чистая функция в `addition.py`. Контроллер связывает это с базой (`PresetStore`), сверкой эталонов после обучения и диагностикой; окно — строка поиска над протоколом, нажатие на подчёркнутое слово («добавить и запомнить» за одно действие) и неблокирующий вопрос в статусе.

**Разбор ТРИЗ (22.10, утверждён):** 1) непонятые слова — самопроверкой, без списка основ; 2) нажатие на подчёркнутое слово = добавить пункт + запомнить слово; 3) после обучения — сверка эталонов и «Отменить»; 4) без таблицы `item_usage` и без схемы v3 — выше пункты, к которым привязаны слова; 5) правка слова снимает подчёркивание только с него.

**Tech Stack:** Python 3.12, sqlite3, tkinter/ttk + sv-ttk, pytest, uv.

**Spec:** `docs/superpowers/specs/2026-10-21-orthofill-0.2-design.md` — этап 3 («Добавить пункт», «Непонятые слова в записи (из разбора ТРИЗ)», «Вопрос «Каким словом…»», «Словарь в разборе записи», «Диагностика этапа 3»).

## Global Constraints

- Версия: `__version__ = "0.2.0b3"`, `VERSION_LABEL = "0.2 beta 3"`.
- Слово запоминается **только** после явного выбора врача («Да» / «Запомнить»). Никакого обучения молча.
- Быстрый путь не меняется: запись → Ctrl+Enter → вставка. Все новые действия необязательны и ничего не блокируют; копирование не ждёт ответа на вопрос.
- Словарь — свой у каждого пресета; слово привязано к **тексту** пункта (код — подсказка).
- Словарь проверяется раньше правил; строка, выбранная словом, — без метки «проверьте».
- Отрицания действуют и на слова словаря («торк отменён», «без торка»).
- Добавить и привязать слово можно только к **варианту** группы или **отдельному пункту**; группа и раздел в поиске — серой подсказкой «где это», сами не выбираются; код пункта врачу не показывается.
- Ручные правки врача в протоколе сохраняются при «Добавить пункт».
- В буфер — чистый текст (как в 0.2b2).
- Коммиты заканчиваются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

Слова с одной основой (`word_stem`) удаляются из записи вместе (все вхождения заменяются пробелами той же длины). Порядок — как в записи.
  - `DictMatch`: внутри движка; `Protocol.dictionary_hits: list[str]` (сработавшие слова), `Protocol.unknown: list[tuple[int, int, str]]`.
  - Словарь в `build_protocol` (до разделов): для каждой записи словаря — фраза найдена в записи (все слова фразы подряд по основам `word_stem`, раскладка — через `norm`) и не отменена (`_cancelled`) → пункт по тексту (`ws` равен), иначе по коду с тем же текстом; не найден → `warn('слово «{word}» больше не находит пункт')`, слово не трогается. Вариант группы → `ctx.forced[group.id] = variant` (в `_select_or_default` — вернуть его без правила и без метки); отдельный пункт → включён (`ctx.forced_singles`). Два слова на разные варианты одной группы → первый по позиции в записи + предупреждение.
  - `tests/cases` формат: необязательное `"dictionary": [["торк", "Изгиб третьего порядка"], …]` на уровне файла.

### Task 3: Поиск и вставка пункта в правленый протокол (`addition.py`)

**Files:**
- Create: `orthofill/addition.py`
- Test: `tests/test_addition.py`

**Interfaces:**
- Consumes: `join_group` (`render.py`), `Workbook`.
- Produces:
  - `@dataclass SearchHit: code: str; label: str; where: str; spans: list[tuple[int, int]]` — `label` — текст варианта/пункта (без кода), `where` — «Лечение → Юстировка дуги» (тексты раздела и группы без завершающего «:»), `spans` — где в `label` совпало набранное (для подсветки).
  - `search_items(wb: Workbook, query: str, limit: int = 7) -> list[SearchHit]` — по вариантам и отдельным пунктам (без разделов/групп), `norm` с раскладкой; все слова запроса должны найтись (по началу слов); ранжирование: совпадение с начала текста → у пункта есть слова в `wb.dictionary` → короче текст. Пустой запрос → пункты со словами словаря (для «добавить для слова»).
  - `insert_item(wb: Workbook, text: str, code: str) -> tuple[str, int]` — новый текст и номер вставленной строки (0-based). Строка — `join_group(группа, вариант)` или текст отдельного пункта. Раздел ищется по строке-заголовку (`ws`-равенство тексту раздела); вставка — после последней строки раздела (до следующего заголовка); если в разделе есть строка другого варианта той же группы **без правок** (равна её склейке) — она заменяется; заголовка нет → раздел (заголовок + строка) вставляется перед первым заголовком раздела, который идёт позже по порядку пресета, иначе в конец.
