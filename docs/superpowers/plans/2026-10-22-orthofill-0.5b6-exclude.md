# Orthofill 0.5 beta 6 — «Ошибка → Исключить» из строки отчёта: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Врач выделяет строку (или несколько) в протоколе → правая кнопка → «Ошибка → Исключить» = этой строки в отчёте быть не должно: строка убирается из протокола, а случай с точными данными (какой пункт, откуда он взялся, запись, протокол) сразу сохраняется для разработчика (заказчик: «это лучше кнопки ошибка отдельно — быстрый путь получить нужные данные об ошибке»).

**Architecture:** Контроллер: `exclude_case(codes, …)` пишет событие диагностики `case` вида `exclude` всегда (явное действие врача, как «Отметить ошибку») и через неё — в телеметрию, если она включена; для каждого кода — `source`: откуда строка (строка оболочки / по умолчанию / всегда / по условию / из записи). Окно: подменю «Ошибка» в меню протокола; исключение — удалением строк (режим оболочки — слой правок холста, «удалённое не возвращается»; режим через запятую — правка протокола); полоска «Исключено: … — Вернуть».

**Tech Stack:** Python 3.12, tkinter, pytest.

**Spec:** запрос заказчика 22.10 (этот план, Goal); `docs/superpowers/specs/2026-10-22-orthofill-0.5-shell-design.md` — «Холст протокола» (удалённая строка); 0.2 «Отметить ошибку» (`Controller.mark_case`, `CASE_KINDS`).

## Global Constraints

- Меню протокола (правая кнопка): подменю **«Ошибка»** — «Исключить — этой строки быть не должно» и «Другое…» (открывает прежнее окно «Отметить ошибку»). Исключаются **строки под выделением**, без выделения — строка под курсором мыши. Строки без кода (свой текст врача, скелет) не исключаются — пункт меню неактивен.
- Исключение = удаление строк из протокола: режим «Оболочка» — через правки холста (`Edits.removed`), строка не вернётся, пока строку записи не напишут снова; режим «через запятую» — как ручная правка (полоска «Обновить/Оставить» — как раньше).
- Событие `case`, `kind='exclude'`, пишется **всегда** (даже без «Диагностики»), как «Отметить ошибку»: `raw`, `entry_id` (если запись подтверждалась), `mode` (`shell`/`comma`), `lines` (протокол), `defaults`, `warnings`, `excluded`: список `{code, text, source}`; `source` ∈ `path` (есть строка оболочки с этим пунктом) · `default` (есть в протоколе пустой записи) · `always` · `condition` · `note` (из слов записи).
- Полоска после исключения: «Исключено: «<текст>» — случай сохранён [Вернуть]»; «Вернуть» возвращает строки (событие `case` `kind='exclude_undo'` с тем же `id` случая).
- Кнопка «Отметить ошибку» остаётся (случаи без конкретной строки: «не хватает пункта»); судьба — по телеметрии (сколько раз какой путь).
- Версия `0.5.0b6` / «0.5 beta 6»; `CHANGELOG.md` «0.5 beta 6».

## Review Focus

1. Выделение захватывает часть двух строк — исключаются обе строки целиком, а не обрезки текста (Task 2 `test_exclude_partial_selection_whole_lines`).
2. Исключение строки группы с вариантом (одна строка «Эластики: Перепел») — исключён вариант, в случае — оба кода группы и варианта (Task 1 `test_exclude_merged_row_codes`).
3. Исключили, потом запись дописали (режим оболочки) — строка не вернулась; «Вернуть» — вернулась (Task 2 `test_exclude_survives_rebuild`, `test_undo_exclude`).
4. Диагностика выключена — случай всё равно сохранён (Task 1 `test_exclude_written_without_diagnostics`).
5. Свой текст и скелет не исключаются (Task 2 `test_exclude_disabled_on_own_and_skeleton`).
