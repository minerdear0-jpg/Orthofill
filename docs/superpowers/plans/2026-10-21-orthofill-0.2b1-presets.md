# Orthofill 0.2 beta 1 — пресеты в SQLite. План реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** программа работает с несколькими пресетами (типами карточек), которые хранятся в SQLite; xlsx — импорт/экспорт пресета; переключатель пресета в окне; эталоны сохраняются в базу; способ выбора варианта — свойство группы (данные), без изменения поведения разбора.

**Architecture:** движок (`engine.py`) по-прежнему работает с объектом `Workbook`; меняется его источник — `PresetStore` (новый модуль `presets.py`) собирает `Workbook` из базы. Свойства групп и пунктов (`method`, `when`, `default`, `words`) живут в `Item`, угадываются при импорте (`engine.guess_settings`) и читаются/пишутся листом «Настройки» в xlsx. Контроллер вместо «открыть файл» умеет «импорт / экспорт / переключить пресет».

**Tech Stack:** Python 3.12, sqlite3, openpyxl, tkinter + sv-ttk, pytest, uv.

**Spec:** `docs/superpowers/specs/2026-10-21-orthofill-0.2-design.md` — этап 1, разделы «Понятия», «Способы выбора», «Переносимость».

## Global Constraints

- Версия: `__version__ = "0.2.0b1"`, `VERSION_LABEL = "0.2 beta 1"` (`orthofill/__init__.py`, `pyproject.toml`, `uv.lock`, `README.md`, `tests/test_version.py`).
- Только tkinter/ttk + sv-ttk, openpyxl, sqlite3 — новых зависимостей нет.
- Формат первого листа xlsx — ровно как в 0.1: заголовок `ID_CLASS | CLASS_LIST | ID_INPUT_RAW | INPUT_RAW | ID_CLASS_RESULT | RESULT`.
- Лист «Настройки»: `Код | Способ выбора | Когда в протоколе | По умолчанию | Слова`. Лист «Словарь»: `Слово | Пункт | Код | Добавлено | Сработало раз`.
- `PRAGMA user_version` → 2; база 0.1 мигрирует без потери `entries`, `settings`, `classifier_snapshots`.
- В JSON в базе — только простые списки/словари (переносимость на C++/Rust).
- Поведение разбора не меняется: все тесты 0.1 beta 3 проходят (кроме явно переписанных в этом плане).
- Отдельный пункт идёт «всегда», если он есть **больше чем в половине** эталонов пресета; без эталонов — всегда.
- Все тексты интерфейса и сообщений — по-русски, простыми словами.
- **Отклонение от описания:** автоматический перевод старых эталонов в новый вид (описание, этап 1 «Импорт») переносится в план 0.2 beta 2 — он меняет режимы вывода строк и должен выйти вместе с новой склейкой. В 0.2 beta 1 эталоны импортируются как есть.
- Коммиты заканчиваются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
