# Orthofill 0.2 beta 5 — логика полей: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Логика пресета И / ИЛИ / НЕ / И-НЕ — в данных: сочетание у групп, условия у пунктов (трёхзначные, только по фактам записи), пары «не вместе»; зашитое `_orphan_applies` становится угаданным условием; редактор — экран A критика.

**Architecture:** `logic.py` — язык условий без Tk: разбор/запись текста xlsx, вычисление (да/нет/неизвестно), ссылки, перекодировка. Движок собирает протокол в два прохода: сперва все группы (с отметкой «из записи / подставлено»), потом пункты по `when` и условиям; пары лишь добавляют «проверьте». Хранение — схема v3; редактор — новые свойства в прокручиваемой панели.

**Tech Stack:** Python 3.12, tkinter/ttk + sv-ttk, sqlite3, openpyxl, pytest.

**Spec:** `docs/superpowers/specs/2026-10-22-orthofill-0.2b4-editor-design.md` — раздел «Выпуск 0.2 beta 5» (с «Ответами на проверку описания») и «Анти-цели». Макеты: `docs/superpowers/mockups/0.2b5/R-wide.png`, `R-narrow.png`, `A-broken.png`.

## Global Constraints

- Строка выводится условием только при «да»; «неизвестно» и «нет» — не выводят. Факт — только из записи: вариант, выбранный по умолчанию пресета или умолчанием встроенного правила (всё, что пишет в `ctx.defaults`), — не факт.
- Условие не выводит строку, которая не следует из записи (анти-цель).
- Только tkinter/ttk + sv-ttk; Canvas — только для прокрутки панели свойств.
- Схема базы v3 с миграцией с v2; описание — `docs/presets-schema.md`.
- Лист «Настройки»: F «Сочетание» (`И`/`ИЛИ`), G «Условие», H «Не вместе с»; экспорт ↔ импорт без потерь.
- Подписи: `WHEN_LABELS['condition'] = 'по условию'`; сочетание — «ИЛИ — один вариант» / «И — все упомянутые варианты».
- Один режим редактора (коды видны). Версия — `0.2.0b5` / «0.2 beta 5»; `CHANGELOG.md` — раздел «0.2 beta 5».
- Тесты окна — настоящий Tk; щелчки — через `_shown`/`_click` из `tests/test_editor_ui.py`.

## Review Focus

1. «НЕ 2b = самолигирующая», тип системы не назван → строка не выводится (Task 2 `test_not_unknown_stays_unknown`, Task 4 `test_not_on_unknown_field_prints_nothing`).

### Task 2: Язык условий (`logic.py`)

**Files:**
- Create: `orthofill/logic.py`
- Test: `tests/test_logic.py`

**Interfaces:**
- Produces:
  - Дерево: узел-группа `{'all': [узлы]}` / `{'any': [узлы]}`; узел-строка `{'field': код, 'is': код}` или `{'field': код, 'mentioned': True}`; у любого узла может быть `'not': True`.
  - `@dataclass Facts(known: dict[str, set[str]], mentioned: set[str])` — `known[группа]` = варианты, выбранные **из записи**; `mentioned` — упомянутые в записи группы и пункты.
  - `evaluate(node, facts) -> bool | None` — трёхзначно: строка `is`: поле не в `known` → None, иначе `is in known[field]`; `mentioned` → `field in facts.mentioned` (двузначно); `not` меняет True↔False, None остаётся; `all`: есть False → False, есть None → None, иначе True; `any`: есть True → True, есть None → None, иначе False.
  - `parse(text: str, codes: set[str]) -> dict` — `ValueError` с понятным текстом («не знаю код 4x», «ожидаю «=» или «И»/«ИЛИ» после «2b»»). Грамматика: `выр := и_выр ('ИЛИ' и_выр)*`, `и_выр := отр ('И' отр)*`, `отр := ['НЕ'] (атом | '(' выр ')')`, `атом := код ['=' код | 'упомянут']`; регистр слов не важен; пустой текст → `None`.
  - `format(node) -> str` — обратно: `2b = 2b2 И НЕ 4p`; скобки — только где нужны; `parse(format(t)) == t` для простых деревьев.
  - `is_simple(node) -> bool` — один уровень `all`/`any` из строк (только такое правится в окне).
  - `refs(node) -> set[str]` — все коды (поля и значения).
  - `remap(node, m: dict[str, str]) -> dict` — коды по таблице.
  - `has_positive(node) -> bool` — есть строка без НЕ на пути «все строки» (для проверки «по условию из ничего»).

def test_parse_format_roundtrip():

    assert t == {'all': [{'field': '2b', 'is': '2b2'}, {'field': '4p', 'mentioned': True, 'not': True}]}

**Interfaces:**
- Consumes: `logic.Facts/evaluate` (Task 2), поля Task 1.
- Produces:
  - `guess_condition(item, wb) -> dict | None` — для пункта (отдельного или сироты), чей текст содержит «фиксаци» и «лигатур» → `{'all': [{'field': <группа rule_kind 'system'>, 'is': <её вариант «лигатур» без «самолигир»>}]}`; «клипс» → вариант «самолигир». Нет группы/варианта → None.
  - `effective_condition(item, wb) -> dict | None` — `item.condition or guess_condition(item, wb)`.
  - `_effective_when(wb)` — теперь и для сирот: `it.when or ('condition' if guessed else 'mentioned')` у сирот; у отдельных — как было.

Правила (описание, «Смысл условий» и «Ответы» 2, 4, 5, 6):
- Проход 1 — все группы по порядку (как сейчас, с теми же предупреждениями); проход 2 — строки по разделам.
- `Facts`: `known` — группы «из записи» с непустым выбором; `mentioned` — группы, упомянутые в записи (в т.ч. выбор `[]`), отдельные пункты и сироты, упомянутые словами (`_single_mentioned` / `_best_by_words`) или словом врача.
- Пункт выводится: слово врача → всегда (если условие ≠ True — `ctx.flag(code, 'по условию строки быть не должно — проверьте')`); `always` → условие нет или True; `mentioned` → упомянут и (условия нет или True); `condition` → условие True.
- Пары: обе строки выведены → `flag` обеим «не вместе с «…» — проверьте» и `warn`.
- И (`combine == 'and'`): «по словам» — все варианты с ненулевым совпадением; эластики — все найденные; юстировка — все найденные порядки. ИЛИ и несколько найденных (эластики > 1; юстировка > 1; «по словам» — равные лучшие при ненулевом совпадении) → все с `flag(group, 'несколько вариантов — проверьте')` и `warn`.
