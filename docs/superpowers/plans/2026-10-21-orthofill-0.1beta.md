# Orthofill 0.1 beta — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Превратить прототип `ortodont_v4.py` в настольное приложение Orthofill 0.1 beta для Windows 11: краткая запись врача → протокол в буфер обмена, классификатор и эталоны в xlsx врача, журнал в SQLite, портативная сборка.

**Architecture:** Пакет `orthofill/` из небольших модулей: разбор записи (`parse`), чтение/запись xlsx (`workbook`), сборка протокола по правилам, привязанным к тексту пунктов (`engine`), журнал (`journal`), логика окна без tk (`controller`) и само окно (`ui`). Всё, кроме `ui`, покрыто pytest и работает без дисплея. Сборка — `build.ps1` (uv + PyInstaller) на Windows.

**Tech Stack:** Python 3.12+ (uv), openpyxl, tkinter + sv-ttk, sqlite3 (stdlib), pytest, PyInstaller.

**Spec:** `docs/superpowers/specs/2026-10-21-orthofill-0.1beta-design.md`

## Global Constraints

- Версия: `__version__ = "0.1.0b1"`, в интерфейсе — `"0.1 beta"`; заголовок окна `Orthofill 0.1 beta`.
- Имена сборок: `dist\Orthofill-0.1beta-portable.zip` (папка `Orthofill\` с `Orthofill.exe`), `dist\Orthofill-0.1beta.exe` (one-file).
- Целевая ОС: Windows 11. Разработка и все тесты, кроме ручной проверки окна, — на Linux.
- xlsx врача — источник правды. Запись в него — только по явному действию «Сохранить как эталон», с подтверждением и резервной копией `<имя>.bak.xlsx`.
- Буфер обмена получает только текст протокола (без кодов), строки через `\n`.
- Плашка в окне, дословно: `Проверьте протокол перед вставкой в служебное ПО`.
- В «О программе», дословно: `Программа формирует черновик протокола; ответственность за содержание несёт врач.`
- База `orthofill.db` рядом с exe; если папка недоступна для записи — `%LOCALAPPDATA%\Orthofill\`.
- Зависимости приложения — только `openpyxl`, `sv-ttk`. Никаких сетевых вызовов.
- Тексты интерфейса и сообщений — по-русски.

## Review Focus

1. **xlsx открыт в Excel при «Сохранить как эталон»** → понятное сообщение `Закройте файл в Excel и повторите`, файл и правки врача не потеряны. Тест: Task 4 `test_append_reference_locked_file`.
2. **Ctrl+Enter при пустом поле записи** → протокол не формируется, буфер не трогается, статус `Введите краткую запись`. Тест: Task 6 `test_generate_empty_raw`.

### Task 3: Сборка протокола по правилам, привязанным к тексту

**Files:**
- Create: `orthofill/engine.py`, `tests/test_engine.py`

**Interfaces:**
- Consumes: `Workbook`, `Item`, `ReferenceCase` (Task 2); `extract_facts`, `parse_wire_from_label`, `norm`, `word_stem`, `stem_in` (Task 1).
- Produces:
  ```python
  @dataclass
  class Protocol:
      lines: list[tuple[str, str]]     # (код, текст)
      warnings: list[str]
      defaults: list[str]              # что подставлено по умолчанию
      @property
      def text(self) -> str            # тексты строк через '\n'
  @dataclass
  class CaseResult:
      case_id: str; ok: bool
      missing: list[tuple[str,str]]; extra: list[tuple[str,str]]
  def build_protocol(wb: Workbook, raw: str) -> Protocol
  def check_references(wb: Workbook) -> list[CaseResult]
  def rule_kind(group: Item) -> str | None   # по тексту группы
  def rule_warnings(wb: Workbook) -> list[str]   # правило без своей группы в файле
  ```

Правила `rule_kind` — по `norm(group.text)` (первое совпадение):

| kind | признак в тексте группы | выбор варианта |
|---|---|---|
| `system` | `тип систем` | по `system_type` (как v4) |
| `stage` | начинается с `этап` | ключевые слова v4; иначе `stem_in` по словам варианта; `None` → «рабоч» + default |
| `mucosa` | `слизист` | как v4; `None` → вариант «без видимых» + default |
| `hygiene` | `гигиен` | как v4; `None` → «удовлетвор» + default |
| `relation` | `соотношение (моляр\|клык)`; сторона `справа/слева` | класс из `classes` |
| `bracket` | `состояние брекет` | как v4; `None` → «удовлетвор» + default |
| `wire` | `смена дуги`; челюсть `верхн/нижн` | `parse_wire_from_label` по каждому варианту |
| `ligature` | `лигатур` и `смен` | `ligature_change`; челюсть `ligature_arches`, `None` → «обеих» + default |
| `binding` | `подвяз` | `binding`, `binding_arches` |
| `elastics` | `эластик` | вариант, чей `word_stem` слов найден в записи |
| `adjust` | `юстиров` | порядок изгиба (как v4) |
| `dynamics` | `динамик` | как v4; `None` → «соответств» + default |
| `visit` | `явк` | число недель из текста варианта; `None` → 4 + default |

Раздел, текст которого начинается с `жалоб`, — выбор одного варианта: ключевые слова v4 (отклеива/отвалил, выход дуги, перелом/сломал дуги), затем `stem_in` по словам варианта длиной ≥5; иначе вариант с `не предьявл|не предъявл` (или первый) + default. Группа без `rule_kind` — вариант по `stem_in` слов ≥5 букв; не найден — группа пропускается. Одиночный пункт уровня 2 (не сирота) — всегда. Сирота — `score_orphan` из v4.

Тексты defaults (дословно): `жалоб нет`, `этап рабочий`, `слизистая в норме`, `гигиена удовлетворительная`, `брекет-система в порядке`, `динамика по плану`, `явка 4 нед`, `лигатуры на обеих челюстях`.

Тексты warnings (дословно, `{…}` — подстановки):
- `дуга на {верхней|нижней}: размер не распознан — выберите вручную`
- `дуга на {верхней|нижней}: {0.016×0.025}" {материал} нет в классификаторе`
- `эластики упомянуты, но вариант не найден в классификаторе` (если `mentions_elastics` и ничего не выбрано)
- `явка через {N} нед: такого варианта нет, выбрано «{текст}»` (выбирается ближайший)
- `rule_warnings`: `в файле нет группы для правила «{kind}»` — для `wire` (верх и низ), `elastics`, `visit`, `system`, `stage`.

Вывод группы с выбранным вариантом — режим из эталонов (`_render_modes(wb) -> dict[str, str]`): в эталоне есть строка с кодом группы и текстом `parent + ' ' + child` → `join`; строка группы с текстом родителя → `separate`; есть только строка варианта → `child_only`. Нет в эталонах: родитель кончается на `:` → `child_only`, иначе `separate`. Строка `join` получает код группы.
